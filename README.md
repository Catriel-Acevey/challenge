# Backend Challenge

REST microservice for managing users and their Pokemon teams. The API is built
with FastAPI, PostgreSQL, and SQLAlchemy, and queries PokeAPI to convert stored
Pokemon IDs into their names.

## Features

- Create users with an email, username, password, and an optional Pokemon team.
- Retrieve all users or a user by ID.
- Partially update a user's data.
- Delete users.
- Enrich responses with Pokemon names fetched from PokeAPI.
- Interactive documentation generated by FastAPI.
- Integration tests using a separate database and a mocked PokeAPI client.

## Stack

- Python 3.14
- FastAPI 0.140
- SQLAlchemy 2
- PostgreSQL 15
- Alembic
- Pytest
- Docker Compose

## Requirements

- Docker and Docker Compose.
- Available ports `8000` and `5433`.
- Internet access to query PokeAPI during normal API usage.

## Configuration

The application reads environment variables through Pydantic Settings. The
repository includes [`backend/.env.example`](backend/.env.example) as a
template for local development. Copy it to `backend/.env` before running the
application outside Docker:

```bash
cp backend/.env.example backend/.env
```

The example is configured for a local backend process connecting to PostgreSQL
through `localhost:5433`. Update the values in `backend/.env` if your local
database uses different credentials or ports.

Docker Compose configures the same variables directly for each container. In
Docker, the backend connects to the `db` service through its internal port
`5432`; port `5433` is exposed on the host. The local `backend/.env` file is not
required when using the Compose scripts.

## Run the application

```bash
chmod +x ./up_dev.sh
./up_dev.sh
```

To run the backend without Docker, first start PostgreSQL and then run:

```bash
cd backend
source venv/bin/activate
uvicorn app.main:app --reload
```

The API will be available at:

- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
- Health check: http://localhost:8000/

To stop the containers:

```bash
docker compose -f docker-compose.yml down
```

To also remove PostgreSQL's persisted data:

```bash
docker compose -f docker-compose.yml down -v
```

## Run the tests

The tests use `challenge_db_test` and include a safeguard that prevents Pytest
from accidentally connecting to the development database.

```bash
chmod +x ./up_test.sh
./up_test.sh
```

The tests can also be run directly in the test container:

```bash
docker compose -f docker-compose.test.yml up --build --exit-code-from backend
```

After the tests finish, clean up the test containers with:

```bash
docker compose -f docker-compose.test.yml down -v
```

## API

All user routes use the `/api/v1/users` prefix. Create and update endpoints
expect a JSON body (`Content-Type: application/json`).

### Create a user

```http
POST /api/v1/users/
Content-Type: application/json
```

```json
{
	"email": "ash@example.com",
	"username": "ash",
	"password": "securepassword123",
	"pokemon_team": [25, 6, 150]
}
```

The response does not expose the password and returns Pokemon names:

```json
{
	"id": 1,
	"email": "ash@example.com",
	"username": "ash",
	"is_active": true,
	"pokemon_team": ["pikachu", "charizard", "mewtwo"]
}
```

### List users

```http
GET /api/v1/users/
```

### Get a user

```http
GET /api/v1/users/{user_id}
```

### Update a user

```http
PUT /api/v1/users/{user_id}
Content-Type: application/json
```

All fields are optional:

```json
{
	"username": "new-ash",
	"pokemon_team": [7, 94]
}
```

### Delete a user

```http
DELETE /api/v1/users/{user_id}
```

Returns `204 No Content` when deletion succeeds.

### Main response codes

- `200 OK`: successful retrieval or update.
- `201 Created`: user created successfully.
- `204 No Content`: user deleted successfully.
- `400 Bad Request`: the email is already registered.
- `404 Not Found`: the requested user does not exist.
- `422 Unprocessable Entity`: the body does not match the expected schema.

## Project structure

```text
backend/
	app/
		api/          # Versioned HTTP routes
		clients/      # External integrations, such as PokeAPI
		core/         # Application configuration
		db/           # SQLAlchemy base and sessions
		models/       # Persisted models
		repositories/ # Data access
		schemas/      # Input and output schemas
		services/     # Business logic
	alembic/        # Database migrations
	tests/          # Tests and mocks
```

## Migrations

Migrations are configured with Alembic. To run them from an environment with
the dependencies and environment variables configured:

```bash
cd backend
alembic upgrade head
```
