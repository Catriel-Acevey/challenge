# Challenge

REST microservice for managing users and their Pokemon teams. The API is built
with FastAPI, PostgreSQL, and SQLAlchemy, and queries PokeAPI to convert stored
Pokemon IDs into their names. Includes a fully functional SPA frontend for
notification management with JWT authentication.

## 🚀 Production Deployment

The application is deployed in production with the frontend hosted on **Firebase Hosting** and the backend hosted on **Render** connected to a **Supabase** (PostgreSQL) managed database.

* **Frontend App:** [https://challenge-notifications.web.app](https://challenge-notifications.web.app)

* [**Swagger UI Docs**](https://challenge-pjym.onrender.com/docs)

## Features

### Backend

- Create users with an email, username, password, and an optional Pokemon team.
- Retrieve all users or a user by ID.
- Partially update a user's data.
- Delete users.
- Enrich responses with Pokemon names fetched from PokeAPI.
- Multi-channel notification system (Email, SMS, Push) with Strategy pattern.
- JWT authentication with OAuth2 password flow.
- Interactive documentation generated by FastAPI.
- Integration tests using a separate database and a mocked PokeAPI client.

### Frontend

- **Vite + React 19 + TypeScript** SPA with hot module replacement.
- **TailwindCSS v4** utility-first styling with custom theme.
- **Dark / Light mode toggle** with localStorage persistence and system preference detection.
- **JWT authentication** flow with protected routes and automatic token refresh.
- **React Query** for server state management with cache invalidation.
- **React Hook Form + Zod** for form validation with channel-specific rules.
  - Email: regex validation.
  - SMS: 160-character limit with progress bar.
  - Push: minimum 10-character token.
- **React Hot Toast** for global error and success feedback.
- **Axios interceptors** for automatic JWT injection and global error handling (401, 400, 404).
- Notification CRUD with channel filtering and status badges.
- **Responsive layout** (mobile-first grid).

## Requirements

- Docker and Docker Compose.
- Available ports `3000` (frontend), `8000` (backend), and `5433` (database).
- Internet access to query PokeAPI during normal API usage.

## Configuration

The application reads environment variables through Pydantic Settings. The
repository includes [`backend/.env.example`](backend/.env.example) as a
template for local development. Copy it to `backend/.env` before running the
application outside Docker:

```bash
cp backend/.env.example backend/.env
```

The example is configured for a local backend process connecting to PostgreSQL
through `localhost:5433`. Update the values in `backend/.env` if your local
database uses different credentials or ports.

Docker Compose configures the same variables directly for each container. In
Docker, the backend connects to the `db` service through its internal port
`5432`; port `5433` is exposed on the host. The local `backend/.env` file is not
required when using the Compose scripts.

### Frontend Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `VITE_API_URL` | `http://localhost:8000/api/v1` | Backend API base URL |

Create a `frontend/.env` file for local development (outside Docker):

```bash
cp frontend/.env.example frontend/.env
```

## Migrations

Migrations are configured with Alembic. To run them from an environment with
the dependencies and environment variables configured:

```bash
cd backend
alembic upgrade head
```

## Run the application

### With Docker (recommended)

```bash
chmod +x ./up_dev.sh
./up_dev.sh
```

This starts all three services:

| Service | URL | Description |
|---------|-----|-------------|
| Frontend | http://localhost:3000 | React SPA served by Nginx |
| Backend | http://localhost:8000 | FastAPI REST API |
| Database | localhost:5433 | PostgreSQL 15 |

### Without Docker

**Backend:**

```bash
cd backend
source venv/bin/activate
uvicorn app.main:app --reload
```

The API will be available at:

- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
- Health check: http://localhost:8000/

**Frontend:**

```bash
cd frontend
npm install
npm run dev
```

The frontend will be available at http://localhost:5173 (Vite dev server).

### Stop the containers

```bash
docker compose -f docker-compose.yml down
```

To also remove PostgreSQL's persisted data:

```bash
docker compose -f docker-compose.yml down -v
```

## Run the tests

The tests use `challenge_db_test` and include a safeguard that prevents Pytest
from accidentally connecting to the development database.

```bash
chmod +x ./up_test.sh
./up_test.sh
```

The tests can also be run directly in the test container:

```bash
docker compose -f docker-compose.test.yml up --build --exit-code-from backend
```

After the tests finish, clean up the test containers with:

```bash
docker compose -f docker-compose.test.yml down -v
```

## Decisions Made

* **Clean Architecture:** Implemented to maintain a clear separation of concerns, ensuring high maintainability, testability, and flexibility for future feature changes or integrations.
* **SQLAlchemy & Pydantic:** Chosen as the ORM and data validation layer due to their seamless integration with FastAPI. They provide strong type safety, efficient database management, and fast execution.
* **Docker & Docker Compose:** Used to containerize the application and database, guaranteeing a consistent, portable, and reliable development and production environment.
* **Pytest & Coverage:** Pytest is the industry-standard testing framework for Python, offering simple syntax and high performance. Includes automated unit and integration testing with `pytest-cov` to ensure code reliability across builds.
* **Vite + React SPA:** Chosen over Next.js for simpler static deployment via Nginx, no server-side rendering required.
* **TailwindCSS v4 with `@tailwindcss/vite`:** Utility-first CSS with native Vite integration and class-based dark mode.
* **React Query:** Server state management with automatic cache invalidation and optimistic updates.
* **Strategy Pattern for Notifications:** Extensible multi-channel notification system (Email, SMS, Push) following SOLID principles.
